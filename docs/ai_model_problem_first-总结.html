⚠ 常见误解 / 认知纠偏

误区：模型越强产品越好，API Wrapper 套壳就能创业。现实：Foundation Model 持续变强已证伪 Wrapper 路线；模型能力趋同后，应用层差距取决于 Engineering Work 投入和成本控制，离模型越近被吞噬风险越大。

一、AI 祛魅：从地震到背景音

AI 背景音化

核心机制：2023 年模型发布像地震，如今更像每周天气预报。开发者看一眼 benchmark、切换 API，能跑就继续搬砖。

关键理解：大家已默认 AI 能做基础工作，兴奋点从「模型本身」转向「给生活和工作带来什么便利、如何降本增效」。

典型场景：中大型公司给工程师每日 AI budget，新模型发布无需逐个研究 matrix，直接切换 API 即可。

相关概念：与「模型军备竞赛」不同，一线更关注实际体感而非 benchmark 分数
原文依据：「模型发布，大家的动作又变成了看一眼 benchmark，然后 API 再介入一下，看看能不能嵌套到自己的 workflow 里面，就继续开始搬砖了」

嘉宾观点 团队管理者关注 Workflow 而非模型本身

作为管理团队的 startup 创始人，更重要的是 AI 如何服务于现有 workflow 和产品 feature，而非追逐每个新模型。

「大家从一个刚接触 AI 的新闻的状态，到逐渐适应了 AI 成为自己生活工作的一部分，从而逐步增强自己对 AI 的一个适用的能力。」

主持人提问 模型差距是在拉大还是缩小？

早期顶尖模型功能趋同，中间两年各厂分化（DeepMind 多模态、xAI 服务自家产品、OpenAI 野心最大），但近半年又收敛到 Coding 赛道。

相关概念：Vibe Coding 正转向 Coding Agent，OpenAI Codex、xAI 收购 Cursor、Gemini 全力 Coding

二、应用层竞争：Engineering + 成本

模型趋同后的应用层博弈

核心机制：模型能力再次趋同 + 应用层 Engineering，最终效果可能趋同，但过程中各团队需投入不同比例的力气在模型 API 上才能达到相同结果。

关键理解：创业者对模型的 sense 比两三年前强得多，会反复测试选择最适合产品 feature 的模型。

典型场景：工作流密集型业务选 Claude；成本敏感选开源自部署，只需付 GPU 消耗费用。

原文依据：「大家都想用最牛逼的模型，但最牛逼的模型也意味着 cost 是最大的」

⚠ 盲目追最强模型

原因：最强模型 API 成本最高，对很多产品而言性能过剩，ROI 不划算。

嘉宾说法：「要根据产品所需的 cost 和 budget 范围之内选择最佳的 allows」

解法：按产品性能需求选型，工作流类优先 Claude，成本敏感用开源 + Fireworks 等部署商。

严重程度：小心

国产模型在硅谷的崛起

核心机制：OpenRouter 上小米、智谱、Kimi 等国产模型 token 调用量已占 50%。硅谷工程师通过 Fireworks 等部署商调用开源国产模型。

典型场景：Cursor 因 Anthropic「背刺」转向用 Kimi Coding 模型做 post-training，xAI 收购 Cursor 提供算力与数据。

原文依据：「Cursor 有很多常识就在模型的 post training，他们其实是在用 Kimi 的一个 coding 的模型做一些额外的训练」

三、一线工作流与 AI 依赖

嘉宾观点 高度依赖 AI，Groq 宕机就摸鱼

所有代码、文案 summarize、报告撰写都用 AI。Groq 宕机时团队自然说「今天大家一起摸鱼」。

「当你找到一个快速的捷径可以让你产生非常好的结果的时候，你就会认为那个就是你现在唯一需要的。当这个捷径被封住了那一天，你会觉得我根本不自在。」

主持人提问 ChatGPT 金融服务值得用吗？

Leo 暂不选择。美股情绪高涨时会夸大增长、掩盖风险，信息越多反而越难筛选有效判断依据。

相关概念：与「AI 帮你理财」的乐观叙事形成对比，嘉宾更担心信息过载

AI 相关股票投资

核心机制：投资反映行业理解 + 个人性格，而非「在 AI 行业所以更谨慎/激进」。

典型场景：AI 相关仓位约 30%–70%，七大科技股最重；曾投 Neocloud 等被看衰标的，因自己分析判断需要。

原文依据：「我并不是很谨慎，我永远是投我自己懂的」

⚠ GPU 抢购热潮

原因：国内外公司大量投入资金抢 GPU 资源，B300 国内价格从 600 多万涨到 1000 万。

嘉宾观察：「虽然招聘说 JAX 是 one level requirement，实际 TPU 使用的中大型公司非常少」

解法：关注 GPU 供应链投资机会，但需区分炒作与实际需求。

严重程度：可忽略（对个人投资者）

五、创业范式转变

⚠ API Wrapper 创业路线

原因：Foundation Model 持续变强，简单套 API 做功能分已被证伪。

嘉宾说法：「很多人是做个 Wrapper，就用 API 的模型简单做一个小分的功能就做成 Startup 了，但现在我非常相信已经证伪了」

解法：聚焦 Vertical 方向 + Domain Knowledge + 快速迭代客户需求。

严重程度：致命

Vertical AI 成功要素

核心机制：大模型公司很难做大部分 Vertical（Coding 是 General Capability 而非 Vertical）。创业者需在行业有 Domain Knowledge，AI 产品与行业 Workflow 匹配。

关键理解：产品逻辑自互联网时代未变：抓住刚需、团队够强、持续迭代 feature。

典型场景：Y Combinator 最新批次：Coding Agent、AI Improv、教授客服等具体场景。

怎么落地：问自己为什么做这个方向，无强烈 motivation 不要做；缺 knowledge 找靠谱合伙人合作

一人公司（OPC）在硅谷

核心机制：融资不错的 Vertical AI 初创团队往往仅几人，AI 可帮干很多事，但 Foundation Model 做不了 Vertical，仍需行业 knowledge 和资源积累。

适用边界：自给自足或体验可以，要融资做大做强则核心需求和产品能力更重要。

嘉宾观点 AI Native SaaS 是未来方向

传统 SaaS 公司组织形态不适合 AI 时代，延续传统 SaaS mindset 是巨大瓶颈。从 0 到 1 做 AI Native Microsoft 三件套或 Salesforce 级客服 Agent，速度更快。

「Manus 就是办公三件套架上的 AI，这件事情最该做出来就是 Microsoft，但是它没有做出来。」

Physical AI 的现实

核心机制：数据是难突破的前提，缺乏丰富多样的机器人数据很难训练泛化模型。

适用边界：春晚等特定场景可完美，换环境/灯光/人员则难以 scale up，发展周期非常长。

相关概念：与 Coding Agent 的短期火热形成对比，Physical AI 仍是理论节点

⚠ 被模型吞噬的风险

原因：模型能力越来越强，离模型越近被吞噬可能性越大，已被 Cursor/Anthropic 案例证实。

嘉宾说法：「大家已经默认模型能力一定会越来越强，你跟模型离得越近，其实你被吞噬的可能性就会越大」

解法：建立分发、用户需求匹配、品牌、社区等护城河，2C 产品尤其重视 community 和 brand。

严重程度：致命

六、三年认知转变

观点对比：三年前 vs 现在

维度三年前（Model First）现在（Problem First）一句话结论
产品逻辑模型够强问题自然解决涉及产品设计、组织流程、用户行为2C 最大问题是用户行为
成本意识以为 cost 不那么重要Token/训练/部署成本越来越重要芯片供应链带动多行业
创业方向穿透传统 SaaS 大公司勇敢做 AI Native，从 0 到 1大公司并未快速干掉创新者
模型选型默认 OpenAI API按性能/成本/场景多模型选型开源 + 国产模型崛起

💡 心法：Problem First

为什么重要：追逐 fancy 科技而做产品，消费者眼里可能是低留存、低频功能。

「现在大家已经从 Model first 转换成一个 Problem first，我认为这才是一个产品的核心逻辑。」
怎么落地：找具体的人、解决具体的问题、让他付钱；回归真实需求而非资本趋势

适用边界：无论互联网还是 AI 时代，本质需求不变；早期模型惊艳 update 让人忽略了这一点

总结与行动

核心要点

  • AI 已从模型发布狂欢祛魅为日常背景音，一线关注 workflow 集成与实际体感
  • 模型能力趋同后，应用层竞争转向 Engineering 投入、成本控制和 Domain Knowledge
  • API Wrapper 创业路线已被证伪，Vertical AI + 行业 know-how 是存活关键
  • 离模型越近被吞噬风险越大，需建立分发、品牌、社区等护城河
  • 三年共识：Problem First 取代 Model First，Token Cost 越来越重要，AI Native SaaS 值得从 0 到 1 探索

行动清单

  1. 审计自己产品的 AI 依赖度：若某 API 宕机业务是否瘫痪？建立降级方案
  2. 按性能/成本/场景建立模型选型矩阵，测试开源和国产模型替代方案
  3. 创业或做产品前问三个问题：为什么做这个方向？Domain Knowledge 从哪来？谁愿意付钱？
  4. 评估产品离 Foundation Model 的距离，强化分发、workflow 匹配、品牌等差异化
  5. 关注 AI Native SaaS 机会：传统 SaaS 组织形态是瓶颈，从 0 到 1 可能更快

关键认知转变

以前认为模型越强产品越好、套 API 就能创业；现在理解了 Problem First 才是核心，Engineering Work 和成本控制决定应用层差距，被模型吞噬是真实且已被证实的风险。

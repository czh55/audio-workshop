四、层次化切片与Agent精简

Hierarchical Chunking and Agent Slimming

情境遵循 Markdown 标题层级切分，500 字符 + 50 重叠区，保留文档元数据实现溯源。语域：casual 技术讲解。

01
中文

核心机制：遵循Markdown标题层级在章节自然边界初次拆分，保证每个单元是完整业务逻辑模块；二次精细分割，最优500字符+50字符重叠区

EN

Core mechanism: follow the Markdown heading hierarchy to do the initial split at natural chapter boundaries, keeping each unit a complete business-logic block; then a finer second pass with an optimal 500-character chunk and a 50-character overlap.

表达提示chunk → 切片；natural boundary → 自然边界；overlap → 重叠区；business-logic block → 业务逻辑模块

02
中文

表达提示blind cut → 一刀切；torn newspaper → 碎报纸；interlocking joints → 咬合缝；semantic coherence → 语义连贯

避坑 PITFALLS

✕ The data and code are very tight together.
✓ Business data was tightly coupled with the code.

「绑定」用 coupled/bound 而非 tight together；这是技术语境的标准表达。

✕ Vector retrieval and BM25 each have 0.7 and 0.3 weight.
✓ Vector retrieval takes a 0.7 weight and BM25 takes 0.3.

take/get/account for 表达权重占比更地道；have weight 略显生硬。

✕ The knowledge base uses Markdown to store, which is very light.
✓ The knowledge base is stored in lightweight Markdown files.

very light 太口语；「轻量化」用 lightweight 作为修饰语更准确。

✕ The AI model can't be fooled if we cut the data at 500 characters.
✓ Blind fixed-length cuts break the logical structure and cause comprehension errors.

500字符不是保险，反而是问题源头；要表达「盲切会破坏结构」这一结论。

认知转变 MINDSET SHIFTS

以为 RAG 效果靠更强的模型和更大的算力 → 架构解耦、知识工程化、混合检索、分层切片——工程细节才是生产力
以为数据库越重越好，企业就该上重型系统 → 中小体量用 Markdown+Git 四两拨千斤，简单工具往往是优选
以为把知识切得越小越好 → 切分要跟随文档结构 + 保留重叠区，固定长度一刀切反而制造逻辑偏差
